Beginner guide

Read this and you are a professional.

You do not need permission, a bootcamp, or a paid account. You need a browser, this page, and six small habits. Work through them in order. Each step points at a real page you can click right now.

  1. 1

    Pick one file and read it out loud

    Open the Explorer and choose one artifact. Read the YAML or playbook line by line. Say what each key does in plain language. If you cannot say it, that is the gap to study — not a reason to stop.

  2. 2

    Run the workflow in the Lab

    The Lab validates the real command shape and shows recorded output. You are practising the sequence, not memorising a screenshot. Type the command instead of reading it.

  3. 3

    Answer three questions without notes

    Use the Quiz. Get them wrong if you must; the explanation is the lesson. Wrong answers return sooner, so the system does the scheduling for you.

  4. 4

    Explain it to another person

    Open the 3D Atlas, pick a node, and explain how it connects to its neighbours. Teaching is the fastest debugger for your own understanding.

  5. 5

    Play one round of Cluster Runner

    The game asks you to make decisions under time pressure while a neural map grows from the concepts you collect. It is revision disguised as play.

  6. 6

    Ship one small change

    Copy a manifest, change one value, apply it in a safe cluster, and observe the difference. Then write down what happened in one sentence. That sentence is experience.

Let's work this out in a step-by-step way to be sure we have the right answer.

Use this sentence every time you are stuck. It turns panic into a procedure.

What you will be able to say

  • “A Deployment manages ReplicaSets, which is why rollbacks have history.”
  • “This Service has no endpoints because its selector does not match the pod labels.”
  • “This image is end-of-life, so I would pin a supported tag before shipping.”
  • “My playbook is not idempotent because the password hash changes every run.”

If you can hold these four conversations, you will know more than most interview candidates.

Questions

The honest answers.

Is the lab a real cluster?

No. It is a browser simulator with recorded output and local validation. That is a deliberate safety choice: you can practise destructive-looking commands without a cloud bill or a broken environment. Every lab says this in the terminal header.

Do I need to install anything?

Not to use the site. Open the live demo, or open docs/index.html in a browser. If you want the exact same local server, run python3 -m http.server inside docs.

Where is my progress stored?

In your browser's localStorage, under a single key. Clearing site data resets it. Nothing is sent anywhere, because there is nowhere to send it.

Can I use this at work or in a course?

Yes. It is MIT licensed. Attribution is appreciated but not required. Do not imply endorsement by KodeKloud, the CNCF, or the vendors named inside the artifacts.

Why do some files have amber notes?

Because the repository is honest about age. A manifest can be a great teaching example and still contain a removed API version, an end-of-life image, or a selector mismatch. The note explains what to change before production.

What makes the 3D pages different?

They are real WebGL scenes, not videos. The atlas is generated from the artifact dataset; the game builds a visible neural map from the concepts you collect. Both pause when the tab is hidden and respect reduced-motion settings.
